# mountd v0.4 — Review Fixes and Roadmap Completion

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This plan is being executed inline in the authoring session.

**Goal:** Fix every finding in `CODEBASE_REVIEW.md` (2026-08-05) and implement the four unbuilt roadmap items from `README.md`, taking mountd from v0.3.0 to v0.4.0.

**Architecture:** All system effects (mount table, mount/unmount, Keychain, TCP probe, Wake-on-LAN) move behind one injectable `Ops` trait, which makes the whole decision surface unit-testable — this is the prerequisite that lets every other fix be written test-first. The per-mount state machine grows from "mounted or not" to a real lifecycle (Idle → Waiting → Attempting → Mounted → Suspect → Recovering) with hysteresis on every transition that can destroy a mount. The reconcile loop becomes per-mount concurrent instead of sequential.

**Tech Stack:** Rust 2021, tokio (multi-thread), serde/toml, clap 4, tracing, libc; IOKit + CoreFoundation via hand-declared FFI (no new crates); AppKit/Swift for the menu bar client.

## Global Constraints

- No new Cargo dependencies. The project deliberately hand-rolls small helpers (e.g. `deps::futures_join_all`) rather than pulling in `futures`; IOKit power notifications are hand-declared FFI rather than an `iokit` crate.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, and `cargo test` must pass at every commit.
- The IPC wire format stays backward compatible: `MountStatus.state` remains a `String` whose prefixes (`mounted`, `error`, `waiting`) the existing Swift client matches on. New structured fields are additive with `#[serde(default)]`.
- No panicking `unwrap`/`expect`/`panic!` in non-test code.
- Credentials never touch disk, never appear unredacted in logs, errors, or IPC responses.
- Every timeout that can span a system sleep must be reasoned about explicitly (macOS pauses the monotonic clock while asleep).
- Target macOS 13+ (`LSMinimumSystemVersion` in the menu bar bundle).

## File Structure

**New files**

- `src/ops.rs` — the `Ops` trait (all system effects), `SystemOps` (real impl delegating to `mtab`/`mountcmd`/`cred`/`probe`/`wol`), and `#[cfg(test)] pub mod fake` with `FakeOps` (scriptable mount table, probe results, mount/unmount outcomes, call log).
- `src/state.rs` — `MountState` enum and its `Display` rendering to the wire strings; `MountRuntime` moves here from `engine.rs`.
- `src/power.rs` — IOKit `IORegisterForSystemPower` FFI on a dedicated CFRunLoop thread; emits `PowerEvent::WillSleep`/`DidWake` on a channel and holds the sleep acknowledgement until the engine reports done or a deadline elapses.
- `src/wol.rs` — magic-packet construction and UDP broadcast send.

**Modified files**

- `src/engine.rs` — holds `Arc<dyn Ops>`; per-mount concurrent reconcile; health/SUSPECT loop; hysteresis; wake settling; migration; pre-sleep unmount; no lock held across awaits.
- `src/reconcile.rs` — `decide()` takes a richer `MountView`; new `Decision` variants `Recover` and `Migrate(usize)`; `Unmount { force: bool }`.
- `src/config.rs` — new policy/defaults fields; mountpoint collision, nesting, and absoluteness validation; retry clamping; per-network error variant.
- `src/mountcmd.rs` — SMB `soft` default; `unmount(mountpoint, force)`; mountpoint normalization; guarded `create_dir_all`.
- `src/cred.rs` — precise newline stripping; `FetchOutcome` instead of bare `Option`.
- `src/probe.rs` — DNS sub-deadline; IPv4-first ordering; probe function injectable for selection.
- `src/deps.rs` — genuinely concurrent `check_all`.
- `src/ipc.rs` — non-fatal `accept` errors, bounded reads, connection timeout, `0600` socket.
- `src/mtab.rs` — normalized mountpoint lookup.
- `src/fingerprint.rs` — timeouts + `kill_on_drop` on `route`/`arp`.
- `src/launchd.rs` — `KeepAlive { SuccessfulExit = false }`, log rotation note.
- `src/bin/mountd.rs` — SIGTERM handling, graceful startup on bad config, power thread wiring.
- `menubar/Sources/main.swift` — off-main-thread Reveal, `mountctl` timeouts, diffed menu rebuild, suspect icon state.
- `menubar/build.sh` — `KeepAlive { SuccessfulExit = false }` for the menu bar agent.
- `.github/workflows/ci.yml` — add a `swiftc -typecheck` step.
- `README.md`, `examples/config.example.toml` — accuracy fixes, "Where things live", new options.

## Task List

### Phase A — Foundation (unblocks testing everything else)

- [ ] **Task A1: `Ops` trait + `SystemOps` + `FakeOps`**
  - Create `src/ops.rs`. `pub type BoxFut<T> = Pin<Box<dyn Future<Output = T> + Send>>;`
  - `pub trait Ops: Send + Sync + 'static` with `list_mounts`, `mount`, `unmount`, `fetch_password`, `probe`, `wake_on_lan`. All async methods take owned arguments and return `BoxFut` so the trait is object-safe without `async_trait`.
  - `FakeOps` records every call and returns scripted results, including per-address probe latency so priority-vs-speed can be tested honestly.
  - Test: `FakeOps` returns scripted mount table; a fake mount records its argv.
  - Commit: `refactor: put system effects behind an injectable Ops trait`

- [ ] **Task A2: `MountState` enum + `MountRuntime` move**
  - Create `src/state.rs`. `MountState { Unknown, Idle, Waiting, Attempting, Mounted { via }, Suspect { via, failures }, Recovering, Unmounted { manual }, Error { message, retry_in } }` with `Display` producing exactly the current wire strings plus `suspect (…)` and `recovering (…)`.
  - `MountStatus` gains `#[serde(default)] state_kind: Option<String>` for structured consumers.
  - Test: every variant renders a prefix the Swift client understands; round-trips through serde.
  - Commit: `refactor: model mount lifecycle as an enum`

- [ ] **Task A3: Engine takes `Arc<dyn Ops>`**
  - `Engine::with_ops(path, cfg, ops)`; `Engine::new` delegates with `SystemOps`. Replace every direct `mtab::`/`mountcmd::`/`cred::`/`probe::` call in `engine.rs`.
  - Test: existing engine tests pass against `FakeOps` with no network or Keychain access.
  - Commit: `refactor: engine drives system effects through Ops`

### Phase B — Critical and High findings

- [ ] **Task B1 (C1 + H4): Unmount hysteresis and wake settling**
  - `Policy::unmount_grace_secs` (default 30), `Defaults::wake_settle_secs` (default 20).
  - `MountRuntime.gone_since`; `decide()` returns `Idle` while `gone_for < grace`, then `Unmount { force: false }`.
  - `Engine.settle_until`: set on `wake_gap()` detection; while settling, conditions-gone never unmounts, and all `next_retry_at` are cleared.
  - Tests: conditions gone for less than the grace does not unmount; sustained past the grace does; a wake immediately followed by a false condition read does not unmount; backoff clears on wake.
  - Commit: `fix: require sustained condition loss before unmounting`

- [ ] **Task B2 (C1b): Policy unmounts never force**
  - `mountcmd::unmount(mountpoint, force)`; ladder is `diskutil unmount` → `umount` and stops there unless `force`, which adds `diskutil unmount force` → `umount -f`. Policy unmounts pass `false`; user unmounts and dead-server recovery pass `true`.
  - Tests: argv for both modes; a busy mount is not force-unmounted by policy.
  - Commit: `fix: reserve forced unmounts for user actions and dead servers`

- [ ] **Task B3 (H1 + roadmap health loop): SUSPECT state and recovery**
  - `Defaults::health_interval_secs` (30), `Policy::health_failures` (3).
  - Keep arm re-probes `mounted_via` on the interval; failures increment a streak, successes reset it; at the threshold the state becomes `Suspect`, and `decide()` returns `Recover`.
  - `Recover` = forced unmount (server is provably unreachable) then fall through to `Attempt` in the same pass.
  - Tests: healthy mount stays `Mounted`; N probe failures reach `Suspect`; `Recover` unmounts and remounts via a live endpoint; recovery does not fire when no endpoint is reachable.
  - Commit: `feat: detect and recover dead mounts via a health loop`

- [ ] **Task B4 (H2): SMB soft mount default**
  - `mount_argv` pushes `-o soft` for SMB when `options` is unset; NFS default unchanged.
  - Tests: default SMB argv contains `-o soft`; explicit options still pass through verbatim.
  - Commit: `fix: mount SMB shares soft by default`

- [ ] **Task B5 (H6): Manual unmount suppression**
  - `MountRuntime.user_suppressed`, set by `force_unmount`, cleared by `force_mount`, reload, and a `when` false→true edge.
  - Tests: after a manual unmount the reconciler leaves it alone; a conditions edge clears the suppression.
  - Commit: `fix: honor manual unmounts until conditions change`

- [ ] **Task B6 (H5): Surface credential failures**
  - `cred::FetchOutcome { Found(String), Missing, Denied, TimedOut, Failed(String) }`; `attempt_mount` records the outcome and refuses a passwordless mount unless `Policy::allow_passwordless` (default false) is set.
  - Tests: missing credential produces an error state naming the Keychain server, not a silent guest mount; `allow_passwordless` restores the old behavior.
  - Commit: `fix: never silently fall back to a passwordless mount`

- [ ] **Task B7 (H7 + M2): Mountpoint normalization and guarded mkdir**
  - `mountcmd::normalize_mountpoint` trims trailing slashes and canonicalizes only the parent; used by engine, mtab lookup, and unmount.
  - `mount()` skips `create_dir_all` when something is already mounted at the path, and wraps it in a 5 s timeout.
  - Tests: trailing slash and symlinked parent both resolve to the kernel's path; mkdir is skipped when mounted.
  - Commit: `fix: normalize mountpoints and never stat a live mountpoint`

- [ ] **Task B8 (M3): Per-mount in-flight guard**
  - `MountRuntime.attempting` check-and-set under the runtime lock in both `reconcile_once` and `force_mount`; `force_mount` returns early when already mounted.
  - Tests: two concurrent attempts produce one mount call; `force_mount` on a mounted share is a no-op.
  - Commit: `fix: serialize mount attempts per mount`

- [ ] **Task B9 (H3): Per-mount concurrent reconcile**
  - `reconcile_once` spawns one task per mount and joins; a slow mount no longer blocks its peers.
  - Tests: with one mount whose op blocks, another mount still reconciles within the pass.
  - Commit: `perf: reconcile mounts concurrently`

- [ ] **Task B10 (H8 + M12 + M13): Menu bar fixes**
  - Reveal in Finder hops to a background queue and passes `isDirectory: true`.
  - `runMountctl` gains a 10 s deadline via `terminationHandler` plus `readabilityHandler` draining; `mountctl`'s `client_request` gains a timeout.
  - Menu rebuild only when `statuses` actually changed (`MountStatus: Equatable`); suspect state gets its own icon and glyph.
  - Verify: `swiftc -typecheck`.
  - Commit: `fix: keep the menu bar responsive against a wedged daemon`

### Phase E — Roadmap

- [ ] **Task E1: Pre-sleep clean unmount (IOKit)**
  - `src/power.rs`: `IORegisterForSystemPower` on a dedicated thread running a CFRunLoop; hand-declared externs for `IONotificationPortGetRunLoopSource`, `CFRunLoopAddSource`, `CFRunLoopRun`, `IOAllowPowerChange`. Message constants `kIOMessageCanSystemSleep = 0xE000_0270`, `kIOMessageSystemWillSleep = 0xE000_0280`, `kIOMessageSystemHasPoweredOn = 0xE000_0300`.
  - On `WillSleep`, the engine unmounts every mount with `policy.unmount_before_sleep` (default true), bounded by `Defaults::sleep_unmount_budget_secs` (default 8), then acknowledges with `IOAllowPowerChange` — always, on every path, including timeout and error.
  - On `HasPoweredOn`, hint the engine and start the wake settle window (replacing the monotonic-gap heuristic as the primary signal; the heuristic stays as a fallback).
  - Tests: the acknowledgement is sent even when unmounting fails or exceeds the budget (tested through a seam over the raw FFI, since IOKit cannot run in unit tests).
  - Commit: `feat: clean unmount before sleep via IOKit power notifications`

- [ ] **Task E2: Opt-in migration to a better endpoint**
  - `Policy::migrate` (default false), `Policy::migrate_confirmations` (default 2).
  - When mounted via endpoint index `i` and some `j < i` is eligible and passes its probe on consecutive health checks, `decide()` returns `Migrate(j)`: polite unmount, then mount via `j`; abandon the migration and keep the existing mount if the polite unmount fails (busy).
  - Tests: migration fires only when enabled, only upward in priority, only after the confirmation count, and never when the better endpoint flaps.
  - Commit: `feat: opt-in migration to a higher-priority endpoint`

- [ ] **Task E3: Wake-on-LAN**
  - `src/wol.rs`: magic packet (6 × `0xFF` + 16 × MAC), UDP broadcast with `set_broadcast(true)`.
  - Config: `[mount.endpoint.wake_on_lan] mac`, `broadcast` (default `255.255.255.255`), `port` (default 9), plus `Endpoint::wol_wait_secs` (default 45).
  - When an eligible endpoint fails its probe and has WoL configured, send the packet at most once per `wol_wait_secs` and record `waking (sent WoL)` state rather than escalating backoff.
  - Tests: packet bytes are exactly 102 bytes with the right prefix and repetition; MAC parsing reuses `normalize_mac`; the packet is not resent inside the wait window.
  - Commit: `feat: wake-on-LAN for sleeping file servers`
