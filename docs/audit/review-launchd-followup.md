**RF-1 follow-up, medium: a signalled launchctl client is treated as a completed error reply.**

At [mountcmd.rs:328](/home/christian/Documents/dev/mountd/src/mountcmd.rs:328), successful pipe collection and `child.wait()` produce `Ok(Output)` even when the child terminated from a signal. Waiting successfully does not mean the client returned an exit code. This path bypasses the timeout/cleanup error handling. At [launchd.rs:95](/home/christian/Documents/dev/mountd/src/launchd.rs:95), only an outer command error becomes `UnsettledMutation`; `out.status.success() == false` produces an ordinary error. That includes a signalled exit, for which `out.status.code()` is `None`.

Concrete source trace, with a proposed disposable reproduction:

1. Start a fresh install with the service absent. Let the fake bootstrap record an accepted pending request, then terminate that client with a signal before changing the loaded marker. For example, replace the deferred helper's sleep with self-directed SIGTERM after it writes `pending`. Keep synthetic server completion under the fixture driver's control.
2. The supervisor collects EOF and reaps the signalled child before its deadline. It returns `Ok(Output)` with a failing status. `launchctl()` converts this into an ordinary error rather than `UnsettledMutation`.
3. At [launchd.rs:129](/home/christian/Documents/dev/mountd/src/launchd.rs:129), the uncertainty guard does not match. Inspection still reports absence, so `verify_mutation()` returns the ordinary error at line 145.
4. At [launchd.rs:271](/home/christian/Documents/dev/mountd/src/launchd.rs:271), install enters rollback. Its bootout precheck sees absence and submits no removal. A fresh install deletes the attempted plist at line 288. An update can restore the previous plist and bootstrap the previous registration, then remove its recovery backup.
5. Release the pending synthetic server mutation. The request can now complete after recovery discarded or replaced its files. This is the original RF-1 failure sequence with signal termination instead of a supervised timeout.
